# PURPOSE

This document explains how to create spoken-word podcast episodes from written scripts with the podcast generator (the `podcast-generator` command). For installation and the full command reference, see `README.md` and `MANUAL.md`.

The tool is general purpose. You write a script as a markdown (`.md`) file, put it in the inputs folder, and get an audio file in the outputs folder. It suits any single-narrator audio content: orientation series, explainers, briefings, audio essays, internal communications, or personal projects.

Audio is generated by **Kokoro**, a free, open-source text-to-speech model that runs **locally on your machine** through the `voxport` package. There is no API key to manage, no per-use cost, and no data leaves your computer.

There are two ways to work:

- **By hand:** write a script → save it in the inputs folder → run `podcast-generator` → get an audio file in the outputs folder.
- **Drop folder:** turn on the watch in the **Podcast Watch** desktop app, then just drop scripts into the inputs folder (from any device, if the folder is cloud-synced). Audio appears in the outputs folder within a few minutes.

---

# HOW IT WORKS

The podcast generator does the following:

1. Finds the scripts to convert: every `.md` file in the inputs folder (batch mode), or a single script named on the command line
2. Reads each markdown file
3. Strips markdown formatting (headers, bold, italics, horizontal rules, links, inline code)
4. Strips the metadata header block (lines like `**Author:** ...`)
5. Strips section label headers (e.g. `### OPENING`, `### PART ONE`, `### CLOSING`) that should not be read aloud
6. Handles italic-only production notes (e.g. `*End of script.*`): skipped before the prose starts, and treated as the end of the script after it
7. Synthesizes the cleaned text locally with Kokoro
8. Saves the audio to the outputs folder using the same base filename as the input
9. Moves the script into the archive folder, so it isn't converted again. A script that fails goes to the archive's `failed/` subfolder with a `.error.txt` note explaining why.

**Usage (batch: convert everything in the inputs folder):**
```bash
podcast-generator
```

**Usage (single file):**
```bash
podcast-generator path/to/my-script.md
```

**Output:** `my-script.mp3` in the outputs folder (the same base name as the input).

The tool loads the Kokoro model once per run and reuses it, so converting several scripts in one batch is efficient. A run with nothing to do exits almost immediately without loading the model.

Because the tool strips formatting, metadata, and section labels automatically, you can keep your script readable and well organized in markdown without those elements being read aloud.

# FOLDERS

Everything lives in one **home folder**: `podcast_generator` in your Documents folder after a `pip install` (the repo folder if you run from a source checkout, or wherever the `PODCAST_GENERATOR_HOME` environment variable points).

```
.env                    your settings (see .env.example)
inputs/                 default inputs folder: your .md scripts go here
outputs/                default outputs folder: generated audio is written here
script_archive/         default archive folder: converted scripts (failed ones in failed/)
generator.log           output of scheduled and Claude-started runs
```

Because the folders are found through the home folder, the tool works no matter which directory you run it from. You can point any of them somewhere else, typically a cloud-synced folder such as `C:\Users\yourname\Sync\podcasts\inputs`. The easiest way is the **Podcast Watch** app (Browse... next to each folder). You can also set `PODCAST_INPUTS_DIR`, `PODCAST_OUTPUTS_DIR`, and `PODCAST_ARCHIVE_DIR` in `.env` by hand. The same folders are used for manual and scheduled runs.

# WRITING A SCRIPT

## Script File Format

A script is a plain markdown file. A typical structure looks like this:

```markdown
# My Episode Title

**Author:** Your Name
**Date:** 20260605
**Version:** 1.0
**Voice:** af_heart

---

### OPENING

The spoken text begins here...

### MAIN CONTENT

More spoken text...

### CLOSING

Closing remarks...

*End of script.*
```

Everything that is **not** a header, metadata line, horizontal rule, or italic-only note is treated as spoken text and read aloud. Write that spoken text as clean prose.

## What Gets Stripped (Not Read Aloud)

- Markdown headers (`#`, `##`, `###`, ...), including section labels like `OPENING`, `PART ONE`, `CLOSING`
- Metadata lines in the form `**Key:** value` (Author, Date, Version, Voice, etc.)
- Horizontal rules (`---`, `***`, `___`)
- Italic-only lines (e.g. `*Source: ...*` or `*End of script.*`), for production notes. **Caution:** once the spoken prose has started, an italic-only line ends the script and *everything after it is dropped*. Use these lines only at the very top or very end of the file, never for a sentence in the middle.
- Inline formatting markers: `**bold**`, `*italic*`, `` `code` ``, and `[links](url)` are removed, but the text inside them is kept

## What Gets Read Aloud

- All ordinary prose paragraphs
- The text inside inline formatting (the words, not the markers)

# SCRIPT WRITING GUIDELINES

These guidelines apply to most spoken-word content. Adapt them to your purpose, audience, and tone.

## Write for the Ear, Not the Eye
- Use shorter, more direct sentences than you would in written prose
- Avoid bullet points, numbered lists, and tables in the spoken portion; they do not translate to audio
- Spell out acronyms on first use, then use the acronym
- Read the script aloud (or mentally) while writing; if it sounds unnatural, revise it
- Vary sentence length to keep the listener engaged
- Prefer the active voice

## Tone and Register
- Choose a tone that fits your audience and purpose, and keep it consistent throughout
- Direct address to the listener ("you will find," "as you begin") helps engagement
- Avoid filler, over-explanation, and condescension

## Pacing and Length
- A comfortable spoken pace is approximately 130–150 words per minute. Kokoro's default pace is brisker (about 175 words per minute); use `--speed 0.9` to slow it down.
- Estimate runtime from word count at a comfortable pace:
  - ~1,300–1,500 words ≈ 10 minutes
  - ~1,950–2,250 words ≈ 15 minutes
- Keep episodes focused: one clear topic or purpose per episode works best

## Structure
A simple, reliable structure for a single-narrator episode:
1. **Opening** (~1 minute): greet the listener, state the topic, and explain why it matters
2. **Main Content** (the bulk): cover the topic in a few logical sub-sections, with concrete, specific details
3. **Closing** (~1 minute): summarize the key takeaways and point to a next step where appropriate

# WORKFLOW

1. **Draft the script** as a markdown file following the format above.
2. **Review and revise** until the script is clean and ready: no leftover outlines, notes, or formatting that should not be read aloud (other than the elements the tool strips automatically).
3. **Save** the file in the inputs folder with a descriptive name (see File Naming below). The Podcast Watch app's **Open** button next to Inputs takes you straight there.
4. **Generate the audio**, either way:
   - **Drop folder:** if the watch is on (check the Podcast Watch app), do nothing. The script is picked up on the next scheduled check (every 10 minutes unless you've changed it).
   - **By hand:** run the tool. To convert every script in the inputs folder:
     ```bash
     podcast-generator
     ```
     Or to convert just one script:
     ```bash
     podcast-generator path/to/my-script.md
     ```
5. **Listen** to the output in the outputs folder. The script itself has moved to the archive folder. To revise and regenerate, edit the archived copy and put it back in the inputs folder.
6. **If the audio never appears,** look in the archive folder's `failed/` subfolder. The script is there with a `.error.txt` note giving the reason.

# FILE NAMING

Use a descriptive, lowercase, hyphenated slug for the script filename. The audio uses the same base name with an audio extension, in the outputs folder.

Examples:
- `welcome-episode.md` → `welcome-episode.mp3`
- `product-overview-ep01.md` → `product-overview-ep01.mp3`

For a numbered series, include the episode number in the slug:
- `myseries-ep01-introduction.md`
- `myseries-ep02-getting-started.md`

If an archived script with the same name already exists, the newly archived copy gets a timestamp added to its name, so nothing is overwritten in the archive. Audio with the same name *is* overwritten in the outputs folder.

# AUDIO GENERATION SETTINGS

Audio generation uses **Kokoro**, a free, open-source text-to-speech model that runs locally. This approach was selected for:

- High voice quality suitable for professional content
- A fully automated pipeline: markdown script in, audio file out
- **No cost and no API key**: the model runs on your own machine
- **Privacy**: no data leaves your computer
- Repeatable and scriptable for future episodes

## Voice, Language, Speed, and Format

All of these are command-line options on `podcast-generator`:

- **Voice:** Default `af_heart`, an American female voice. Kokoro voice names encode the accent and gender: the first letter is the accent (`a` American, `b` British), the second is gender (`m` male, `f` female). Other examples: `am_onyx`, `am_echo`, `af_nova` (American), `bm_george`, `bf_emma` (British). `MANUAL.md` lists every voice the tool accepts. There are two ways to set the voice, in order of precedence:
  1. **For the whole run:** pass `--voice <voice>` on the command line. This overrides every script's `**Voice:**` line and is handy for quick experiments.
  2. **Per script (recommended):** add a `**Voice:** <voice>` line to the script's metadata header (e.g. `**Voice:** af_heart`). Each script can then have its own voice, which is ideal for batch and drop-folder runs. The line is stripped from the spoken text automatically.
  If neither is set, the default `af_heart` is used. Drop-folder runs never pass `--voice`, so per-script voices are the way to vary voices there.
- **Language (`--lang`):** Derived automatically from the first letter of the chosen voice (`a` American, `b` British), so it always matches the voice. Pass `--lang` only to override that.
- **Speed (`--speed`):** Default `1.0`. Use a smaller number for slower speech (e.g. `0.9`) or larger for faster (e.g. `1.1`).
- **Output format (`--format`):** Default `mp3`. Use `wav` for an uncompressed file that needs no extra dependencies.

**Examples:**
```bash
podcast-generator                                     # convert everything in the inputs folder
podcast-generator --voice af_heart --speed 1.1        # force one voice for the whole run
podcast-generator path/to/my-script.md                # single file, using its own **Voice:** line
podcast-generator path/to/my-script.md --format wav --output episode01.wav
```

The defaults are defined near the top of `podcast_generator/generator.py` if you want to change them permanently.

# DROP FOLDER MODE AND THE PODCAST WATCH APP

Drop folder mode is the same batch command, run automatically every few minutes by a Windows scheduled task named `PodcastGeneratorWatch`. Only one conversion runs at a time, so a check that comes round while a long script is still converting simply leaves it to finish.

Day to day, use the **Podcast Watch** app: run `podcast-watch`, or make a desktop shortcut for it once with `podcast-watch --shortcut`. Its window lets you:

- **Set up the watch** the first time, with one click (Set up watch). No admin rights are needed.
- **Turn the watch on or off.** Off only pauses the schedule; scripts already in the inputs folder wait there until it's back on.
- **Choose what happens when the app opens:** leave the watch as it was, or always turn it on, or always turn it off.
- **Change how often it checks** (Check every, 5 to 60 minutes).
- **Pick the inputs, outputs, and archive folders** (Browse...), open them in File Explorer (Open), or go back to the folders inside the home folder (Use default).

Settings are saved to `.env` and take effect on the next run. Each scheduled run's output goes to `generator.log` in the home folder. `MANUAL.md` has a screenshot and the details.

## From Claude Desktop

If you'd rather ask an AI to write and voice an episode for you, `podcast-generator-mcp` connects podcast_generator to Claude Desktop (or another MCP app). Claude can then queue a script, start the conversion, and tell you when the audio is ready, all from the chat. To set it up, install the tool with `uv tool install "podcast-generator[mcp]"` (or pipx), run `podcast-generator-mcp --config` to print the entry for Claude Desktop's config file, then fully quit and restart Claude Desktop. "Using it from Claude Desktop (MCP)" in `MANUAL.md` has the steps, how to check the connector is installed, example prompts, and how to upgrade. The script-writing guidelines above apply just as much when Claude writes the script, so it's worth pointing Claude at this document.

# REQUIREMENTS

- Python 3.10 or later
- `pip install podcast-generator` (ideally in a virtual environment), which also installs `voxport`, Kokoro and torch. See `README.md` for the details.
- **Recommended:** `espeak-ng` installed on your system. Kokoro uses a built-in dictionary for common English but falls back to espeak-ng for unusual words, names, and numbers. Without it, basic scripts still work but some words may be mispronounced. On Windows, install it from the [espeak-ng releases page](https://github.com/espeak-ng/espeak-ng/releases) (run the `.msi` installer).
- **For MP3 output:** a recent `soundfile`/libsndfile build with MP3 support (common in current versions), or `ffmpeg` on your PATH. The tool tries libsndfile first and falls back to ffmpeg automatically. WAV output needs neither.
- **First run:** the Kokoro model weights (~330 MB), each voice pack, and spaCy's small English model (`en_core_web_sm`) are downloaded automatically. Later runs work offline.
- **For drop folder mode:** Windows. The Podcast Watch app's Set up watch button creates the scheduled task.
- **For use from Claude Desktop:** the `mcp` extra, ideally installed as a tool: `uv tool install "podcast-generator[mcp]"`
- A finalized markdown script following the format described above

# RUNNING BEHIND A CORPORATE FIREWALL (E.G. AT THE OFFICE)

Kokoro downloads its model weights, plus each voice pack (e.g. `af_heart.pt`), from Hugging Face the first time each is used. They're cached in Hugging Face's standard location (`%USERPROFILE%\.cache\huggingface`), or wherever `HF_HOME` points. A corporate network can break these downloads in two ways: huggingface.co may be blocked outright, or an SSL-inspecting proxy (Zscaler, Netskope, Palo Alto, etc.) re-signs the connection with the company's own root certificate, which Python's bundled `certifi` trust store doesn't know. The second shows up as `[SSL: CERTIFICATE_VERIFY_FAILED]` even though `pip install` itself succeeded (pip may be going through an internal mirror).

Two fixes:

**Quick fix (SSL errors only):** trust the operating system's certificate store instead of `certifi`'s bundled list:
```bash
pip install pip-system-certs
```
Windows already trusts the corporate proxy's certificate (that's why your browser doesn't complain), so this usually resolves the SSL errors with no other configuration.

**Robust fix:** avoid the network entirely at work:
1. On a machine where downloads work (e.g. home), add `HF_HOME=<some folder>` (e.g. `HF_HOME=C:\hf_cache`) to the home folder's `.env`, then run the tool once with each voice you plan to use at work, so the model and those voice packs land in that folder.
2. Copy that folder to the work machine (USB drive, approved file share, whatever your IT allows) and add `HF_HOME=<where you put it>` to the work machine's `.env`.
3. Set `HF_HUB_OFFLINE=1` on the work machine. Either add the line `HF_HUB_OFFLINE=1` to the home folder's `.env`, or set it permanently via System Properties → Environment Variables. This tells Hugging Face's client to use the local cache only, which also sidesteps the SSL issue. With it set, only voices already in the cache work.
4. Install spaCy's English model while you still have a network connection somewhere, since `HF_HUB_OFFLINE` doesn't cover it: `python -m spacy download en_core_web_sm` (or copy a virtual environment where it's already installed).

Other firewall problems, such as a blocked Hugging Face download CDN or a blocked GitHub (where spaCy's model normally comes from), are covered in "Behind a corporate firewall or proxy" in `MANUAL.md`. If the computer is managed and blocks new `.exe` files or installs, see "Managed or locked-down computers" there. "Offline use" in `MANUAL.md` and `voxport`'s README have more detail.

# TROUBLESHOOTING

- **The audio never appeared:** Check the archive folder's `failed/` subfolder for the script and its `.error.txt` note. If it isn't there either, check that the watch is on and that the script is in the inputs folder the Podcast Watch app shows, then wait for the next check (or run `podcast-generator` by hand to see the output directly).
- **"no spoken text found after stripping the markdown":** An italic-only line partway through the script ended it early. Remove or rewrite the line that's wrapped entirely in `*asterisks*`.
- **"script requests unknown voice":** The `**Voice:**` line names a voice the tool doesn't accept. Check the spelling (underscore, not hyphen: `af_heart`) against the list in `MANUAL.md`.
- **`OMP Error #15` or `WinError 127` (shm.dll) on import (Windows/conda):** A PyTorch OpenMP DLL conflict common in conda/miniforge environments. Use a plain `python -m venv` environment as described in `README.md`, or set `KMP_DUPLICATE_LIB_OK=TRUE` (the line can go in `.env`).
- **Pronunciation of unusual words or numbers sounds off:** Install `espeak-ng` (see Requirements).
- **MP3 output fails:** Rerun with `--format wav`, or install `ffmpeg` and put it on your PATH.
- **Episode is shorter/faster than expected:** Kokoro's default pace is brisk (~175 words per minute). Use `--speed 0.9` to slow it down.
- **`[SSL: CERTIFICATE_VERIFY_FAILED]` on a Hugging Face URL (common on corporate networks):** See "Running Behind a Corporate Firewall" above.
- **The Podcast Watch app says "Watch not set up":** Click Set up watch.
- **"Another conversion run is already in progress":** Not an error. Only one conversion runs at a time, and the one already going converts the queue.

`MANUAL.md` has more troubleshooting entries.
